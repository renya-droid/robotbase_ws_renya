# 中之島エレベーター（ATC4 → ATC6）

出発地図は `atc4.yaml`、切替先は `atc6.yaml`。ドア面は画像左側の通路入口からかご側へ0.40 m奥です。ドア面より奥の通路と先端の丸い部分を合わせて、10頂点の凹多角形でかごを表します。ドアからかご内側は、両地図とも map の +X 方向です。

| 地図 | ドア左端 (x, y) [m] | ドア右端 (x, y) [m] |
| --- | --- | --- |
| ATC4 / 出発 | (227.001, 13.461) | (227.001, 12.661) |
| ATC6 / 到着 | (2.006, 0.374) | (2.006, -0.426) |

`geometry_review.png` のオレンジ線がドア、水色線がかご外周です。`geometry_pixels.yaml` に補正後の画像ピクセル座標を保存しています。ATC6側は現在の地図原点と既存の校正済みmap座標を一致させるため、小数ピクセルで表しています。座標は各地図YAMLの解像度・原点を使い、画像の上下反転を含めてピクセル中心から変換しました。PGM画像は変更していません。

`switch_map_before_exit: true` により、退出前にATC6へ切り替えます。`arrival_exit_mode: manual` により、人が目的階を確認し、到着側の地図・自己位置・開扉を確認した後、操作GUIの「④ 地図・退出目標を確認して退出を許可」で退出を開始します。車体全体の退出・停止と通常走行設定の復帰が確認できたら、ウェイポイント走行を `atc6.yaml` の1番から再開します。出発側は `atc4.yaml` の146番でエレベーターへ引き継ぎます。ROS domain は既存の実機設定から54を継承しています。

2026-11-28の `1128_4` rosbagをオフライン解析し、記録開始170〜200秒の閉扉中に `/hokuyo_scan` の外壁面と扉面を同一スキャン内で比較しました。扉は外壁より約0.393 m奥にあり、従来のドア座標は通路入口を指していました。地図解像度0.05 mに合わせてドアXを+0.40 m補正し、かご多角形の手前2頂点・X最小値・ドア基準の奥行上限を整合させました。ATC6側は同じ物理扉の奥行補正を適用したもので、到着側の独立したbag計測ではありません。両地図のドアを同じ量だけ補正することで、地図切替時の自己位置変換を維持しています。ドア幅・Y座標・奥側のかご形状・waypointは従来どおりです。

補正前ファイルと検証結果は `~/robotbase_ws_renya/backups/elevator_coordinates_1128_4_20261128/`、比較画像は `~/robotbase_ws_renya/DOCS/analysis/elevator_1128_4_review.png` に保存しています。bag後半には自己位置と地図のずれもあり、この固定座標補正で自己位置ずれ全体が解消するわけではありません。`site.yaml` の既存確認設定は変更していません。設定は以下で検証できます。

```bash
ELEVATOR_PROFILE=nakanoshima python3 ~/kuwa_ws2/tools/configure.py check
```

形状のくぼみに対応するため、`arrival_geometry.py` は単純な凹多角形も受け付けます。自己交差・重複辺の退化形状は拒否し、車体の頂点だけでなく辺もかご壁を横切らないか確認します。
