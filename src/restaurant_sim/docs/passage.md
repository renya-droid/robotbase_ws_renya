# 対向時の有限退避（反復5、未完了）

従来は人物を動的障害物とした目的地へのA*が失敗すると、その場で同じ探索を繰り返していた。座面対応後のlow/mediumではcustomer_04の帰席とcustomer_02の会計行きが対向し、190.4 sim秒で20秒の停止監視が失敗した。

`passage.py`は通常経路の再探索失敗時、1.1m以内の歩行中の相手に限定して退避予約を試す。意図的な着席・サービス待ちは退避させない。最初の要求sim時刻、同時なら永続人物名で通過優先を試し、安全な候補がなければ役割を反転する。これは対になる要求の局所優先であり、出入口や設備のFIFO、公平性の全体保証ではない。

既存0.15mグリッド、距離0.30〜1.8mの有限候補から、退避線分が全家具と実在する全人物に対して掃引可能な候補を調べる。直接見通せる候補のうち最大24件について、相手が退避先の占有を避けて元の目的地へ進めることを確認する。家具の0.29m膨張と人物間0.66mは保持する。どちらにも安全な経路がなければ予約しない。

退避先は他人の歩行・座席遷移にも占有領域として提示する。予約者は通常速度上限内で退避し、そこで止まる。相手が元の対向位置から1.2m以上進んだ後、予約を解放して元の行動を再開する。退避者の行動index、食事・サービス時間、20秒/0.10mの停止履歴をリセットしない。予約は15sim秒で期限切れ失敗となる。失敗を通過成功や待機完了へ変換しない。予約・解放は`PASSAGE`ログとロジック再現JSONの`passage_events`に残す。

反復5のseed42純粋ロジックではlow5人とmedium10人が全員完走。high18人は北通路で停止が残る。全目的地までの動的経路を必要とするため、遠方の別の閉塞も局所退避を妨げる。曲がった経路での退避、複数人物の依存解決、設備FIFO、進行経路全体の予約は未実装。有限候補でも同期A*を繰り返す計算時間は大きく、ROS/Gazebo欠測への影響も未解決。全seed、独立Gazebo実測、G3/G4全体の合格を意味しない。

証跡と残存停止座標は`artifacts/restaurant/issues/5/`および両PROGRESS.mdを参照。家具・椅子・壁・元layout・既存SDF・人数・衝突設定・研究用EVALUATIONは今回変更していない。

# 曲がった退避と解放条件（手動修正 2026-10-30）

直線で見通せる退避先しか探さなかったため、テーブル間の斜めの1人幅通路（high seed42/22の(12.0,4.5〜5.3)付近）では通路外の退避先が候補にならず停止していた。退避者から経路長3 m以内を一度だけ探索し（`Passage.retreats`、通常歩行と同じ家具0.29 m膨張・人物0.66 m掃引検査）、曲がった退避経路を許す。通過者の「退避者がいない場合の経路」から0.71 m以内の退避先は、閉塞を移すだけなので候補から外す。

解放条件に「通過者が目的地（列の待機位置を含む）に着いた」「通過者が列に並び前の人に1秒以上塞がれている」を追加した。これに伴い「通過者の目的地が衝突点から1.2 m以内なら予約しない」という事前条件は削除した（seed11の北通路の対面がこれで解けなかった）。
