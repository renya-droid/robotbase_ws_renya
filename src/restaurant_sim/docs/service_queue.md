# 会計・給水の順番待ち（手動修正 2026-10-30）

全員が同じ会計点を目標にしていたため、2人目が0.66 m手前で止まり続けた。`service_queue.py` は設備ごとのFIFOと容量（既定1）を持ち、先頭だけを設備点へ、他は `config/service_queues.json` の待機位置へ向かわせる。待機位置は図面にない仮定で、会計は南西の開けた区域へ伸びて最後尾が客席側を向き、給水は南壁沿いに西へ伸びる。間隔0.70 m。

列での待ちは停止監視（20秒/0.10 m）から外し、評価基準G3の「明示サービスキューは別集計し120秒以内」に合わせて `max_wait_sim_seconds`（120）で別に判定する（`QUEUE_TIMEOUT`）。

待機位置がすべて埋まっているとき、次にその設備へ向かう着席者は立ち上がらずに座って待つ（`seat_hold_seconds` に記録）。立ち上がり途中の人も列の人数に含める。通路に人があふれて会計へ向かう人が店内を迂回し続ける現象への対策で、行動上の仮定である。

塞がれた歩行者が他人を障害物に再探索した迂回路が、元の経路の1.5倍＋3 mを超える場合は採用せず、その場で待って退避（passage）を依頼する。最大約27 mの迂回で120秒さまよう例があった。

時間: 行動は0.1 s固定刻みで進み、遅れたタイマー周期の分も捨てずに後で処理する（1 tickあたり最大10刻み、残りは `behaviour_lag_seconds` として配信）。時計の巻戻りは `CLOCK_BACKWARDS` として失敗扱い。`failure_policy:=log` では停止・期限切れ・巻戻りを記録して続行する（既定 `fail`）。

着席者は椅子の内側にいて椅子が既に0.29 m膨張の静的障害物（中心から0.48 m以上）なので、歩行者用の0.66 m離隔の対象から外した（`Controller.blocks_walking`）。
