# ココちゃん駆動系同定結果

実施日時: 2026-09-25

## 試験条件

- 入力: `/cmd_vel`（同定中は `twist_mux` を一時停止してドライバへ直接入力）
- 出力: Roboteqエンコーダ由来の `/odom.twist`
- 車輪接地状態で前後走行およびその場旋回
- 設定: `speed_scale=0.70`, `kp_soft=0.30`, `min_speed_threshold=0.12`
- オドメトリ速度は約100 msのエンコーダ窓で推定

- ゲイン中央値: **0.782**

近似モデル:

```text
v(s) / v_cmd(s) ≈ 0.782 exp(-0.154 s) / (0.051 s + 1)
```

時定数は100 msの速度推定窓より短く、モータ単体の時定数としては測定分解能が不足している。遅れにはシリアル通信とエンコーダ速度推定窓が含まれる。

## 実装上の確認事項

`open_loop=false` という設定名に反して、通常の速度コールバックはRoboteqへ `!G` 出力指令を送る。Roboteq本体のKP/KI/KDはすべて0に設定され、ホスト側の `kp_soft` が追加補正を行う。したがって今回得た値は、モータ単体ではなく、ドライバの指令整形・Roboteq・モータ・減速機・車輪・床面・エンコーダ推定を含む駆動系全体の値である。

## 校正の目安

0.30 m/s付近の直進追従を1.0へ合わせる計算値は次の通り。

```text
speed_scale_new ≈ 0.70 / 0.807 = 0.87
```

低速側のゲインが異なるため、`speed_scale` だけですべての速度域を同時に一致させることはできない。変更する場合は0.02程度ずつ上げて再試験する。

## 低速旋回しきい値

`min_speed_threshold=0`を許可するようドライバを修正し、低速底上げなしで静止摩擦試験を行った。

- 底上げなし: `±0.10〜±0.40 rad/s`指令では左右とも始動しない
- `min_speed_threshold=0.10`: 左右とも始動し、定常角速度は約`±0.317 rad/s`
- 旧値`0.12`: `0.40 rad/s`指令時に約`0.407 rad/s`

確実な始動が確認できた最小値として`min_speed_threshold=0.10`を採用した。これにより最低旋回速度を約22%下げる。さらに低速化するには、一定の最低出力を常時適用する方式ではなく、始動時だけ出力を上げて回転後に下げる制御が必要になる。

低速旋回データ:

- `20260925_202155_angular_low.csv/json`（実効しきい値0.10）
- `20260925_202449_angular_low.csv/json`（底上げなし）

## 車輪円周校正

`wheel_circumference=0.6283 m`で直進距離を測定した。

- 1回目の前進odom距離: `2.50626 m`
- 同距離の後退odom距離: `2.50197 m`
- 2回目の前進odom距離: `2.50791 m`
- 2回目の床上実測距離: `2.420 m`
- odomの過大率: `3.633%`

補正式:

```text
0.6283 × 2.420 / 2.50791 = 0.606276
```

実機設定は`wheel_circumference=0.60628 m`とした。これはタイヤの公称幾何寸法ではなく、床面・荷重・タイヤ変形を含む有効転動円周である。

補正後の再確認では、odom `2.42417 m`に対して床上実測が`2.400 m`で、まだ`1.007%`長く出ていた。再補正は次の通り。

```text
0.60628 × 2.400 / 2.42417 = 0.600236
```

一連の床上実測は手測定の誤差を十分に分離できないため、校正値として採用しない。実機設定は元の`wheel_circumference=0.6283 m`へ戻した。上記データは参考記録としてのみ残す。
