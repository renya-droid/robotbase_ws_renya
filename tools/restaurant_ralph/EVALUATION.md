# 研究用受入基準（これから実装するgate）

これは現在合格済みの一覧ではない。閾値は開発用の受入目標であり実店舗での安全保証ではない。測定はsim秒、位置はGazebo ground truthとTF変換済みROS出力を併用。意図的待機(SEATED/GETTING_WATER/PAYING)と移動不能を分ける。接触判定は実形状を使用し、中心間距離のみで矩形ロボットを評価しない。

| Gate | 試験と合格条件 |
|---|---|
| G0 再現ビルド | 新規build/installから必要パッケージと依存をビルド。pytest/colcon test失敗0。4 SDF構文検証、生成2回の同一出力、JSON→SDF中心・寸法・角度誤差<=1 mm/0.001 rad。全ID一意。 |
| G1 図面 | 元画像上の区画・入口・テーブル群と生成top viewを並べた資料。各物体に図面参照/推定の区別、採用スケール、誤差、不明設備の根拠。既存6+4+5+5+1テーブル群を維持、変更には根拠。画像との一致を捏造しない。 |
| G2 行動 | low/medium/high×seed 11,22,33,44,55、各1200 sim秒以内に全員が予定行動を完了して退店。初期着席以外は入口を通る。入席、離席、給水、帰席、会計、退店の順序を状態ログで確認。同行2人と片方給水、散歩客、給水しない客を含む。給水/会計資源の同時占有<=設定容量。未完走・消失は失敗。 |
| G3 動き | 毎sim tickの掃引形状で人と壁/家具/人の侵入<=0.01 m。着席中の位置偏差<=0.02 m。移動状態で20 sim秒以上、進行距離<0.10 mの区間が無い（明示サービスキューは別集計し120秒以内）。入口出現と退店後の非表示以外の瞬間移動禁止。速度上限と加速度上限を設定・検証。 |
| G4 ROS契約 | 全人物の永続ID、位置、向き、立位/座位、行動、速度、timestampを取得。10 Hz目標、受信間隔p95<=0.2 sim秒、最大欠測<=0.5 sim秒。Gazebo実位置との差p95<=0.10 m、最大<=0.25 m。姿勢遷移が0.2 sim秒以内に反映。TF未知/古いodomを黙って使用しない。退出した人がcostmapに残らない。 |
| G5 回帰負例 | 対向狭路、交差、着席者の横、入口混雑、給水列、会計列、通路閉鎖、Gazeboサービス失敗、clock停止/巻戻り、古いロボットodomを試験。負例（壁貫通、全員停止、姿勢欠落、人物削除、通信断）を評価器に注入し、各々非ゼロで失敗すること。 |
| G6 Nav2 | robotの実footprintと0.10 mの静的余裕を用いて配膳目標を検査。基地→3つ以上の客席配膳位置→基地を各scenario×5 seedsで実行。各goal上限180 sim秒、base成功率100%、混雑時>=90%。物理接触0、測定境界間隔>=0.05 m。障害物の消去と迂回を検査。成功率だけで安全性を代用しない。 |
| G7 研究記録 | 到着率、時間、距離、最小境界離隔、停止時間、near miss(<0.2 m)、人の待ち/完走率、TF/通信欠測、RTFをCSV/JSONで保存。生ログ/rosbagとの集計一致。比較条件は同じseed/goal/footprintで揃える。seed 11は同一条件で2回実行し、純粋行動ロジックのtrace hash一致、Gazebo実行では時間差<=5%を検査。不一致は報告。 |

実験の一次比較: 人なしbaseとlow/medium/high。二次比較: センサーのみとground-truth人位置costmapを追加した条件。後者を実カメラ性能と呼ばない。CIの高速smokeと全研究suiteを分離し、smokeだけで完了しない。

評価ランナーはtimeout、終了コード、stderr、missing/skippedを扱い、全gateのJSON結果を出すこと。研究gate未実装/未実行は必ず失敗として扱う。既存単体テストはnode点だけで線分通過・物理接触を保証していないため、独立の掃引判定を追加すること。
